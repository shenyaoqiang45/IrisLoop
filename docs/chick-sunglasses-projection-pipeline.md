## 2. 为什么不能直接沿用标定板的 H

玩偶位于标定板前方，脸又有曲率。同一个投影像素落到不同深度，产生明显视差：

- 把板面 `H⁻¹` 预测的相机 `(575,450)` 作为中心探针初值。
- 实拍相对预测约偏移 **(-128.31, +3.12) 相机像素**。
- 因而板面标定的“亚几像素误差”不能转移到玩偶脸上。

这次采用 **平面初值 → 单点视差平移 → 局部 12 点二次映射 → 整图实拍反馈**。它是固定姿态下的经验光学映射，不是完整三维重建，也没有求玩偶网格、深度图或物理材质。

## 3. 设备与采集设置

设备、桥接、组 1 单帧播放、UTF-8 JSON-RPC 和正常退出方式沿用[五圆流程](five-circle-projection-pipeline.md#2-设备与运行前提)。

| 项目 | 本轮设置 |
|---|---|
| 相机 | 1280×1024；15000 μs；8 dB |
| 采集 | 每次打开后丢弃 4 帧，平均 10 帧，随后关闭相机 |
| 投影 | 640×480、1bpp；上传后等待 2.5 秒 |
| 脸部检测 ROI | 相机 `x∈(375,758), y∈(410,556)` |
| 探针检测 | 背景增量 >12；紧凑连通域面积 6–1000 px |
| 播放 | 最终单帧循环 3600 秒，正常断开 BLE 后继续显示 |

玩偶白色表面比黑圆反射强，不应直接沿用五圆阶段的高曝光。背景与投影帧必须使用相同采集参数。

实验入口为 [tools/chick_sunglasses.py](../tools/chick_sunglasses.py)，复用 [aim_five.py](../tools/aim_five.py) 的桥接和串行采集封装。需要私有桥接仓库访问权限；命令示例：

```powershell
python tools\chick_sunglasses.py --help
# 先确认玩偶眼部与本文固定目标区域一致，再采一张本地姿态参考
python tools\hik_smoke.py --serial K65564865 --exposure 15000 --gain 8 --out captures\procalib\chick_reference_local.png
python tools\chick_sunglasses.py --address F4:12:FA:B6:B7:CA --reference captures\procalib\chick_reference_local.png --seed captures\procalib\five_circles_20261027_100519\live_homography.npz
```

除 `--help` 外，上述命令操作真实硬件。脚本支持 `--bridge`、`--serial`、`--out`；新输出目录不得覆盖旧实验。`--reference` 是必须提供的本地图像，不随公开仓库分发。旧标定仅适合相同装置作为初值；更换装置应先执行五圆流程。

## 4. Pipeline

```text
拍当前玩偶 → 在相机坐标中设计墨镜
→ 单一 BLE 会话、首帧清组 1、黑图背景
→ 模板检查玩偶未移动
→ 中心单点补偿深度视差
→ 12 点测量局部曲面映射
→ 将目标掩模反向采样到投影仪位图
→ 投射、比较实测轮廓
→ 对右镜片作局部反馈修正
→ 三次验收 + 断连后复验 → 保持投射
```

### A. 先把“戴在哪里”变成明确的目标掩模

基于本地初始实拍 `captures/procalib/chick_sunglasses_initial.png` 及眼部放大图，人工观察确定眼睛位置，在相机 1280×1024 画布上生成二值墨镜：

- 左镜片主体约 `x=427–552, y=458–507`。
- 右镜片主体约 `x=594–716, y=455–505`。
- 中间用 9 px 折线连接，两侧短镜腿约 8 px 宽。
- 保留眉毛和喙的主要区域，不用一整条矩形覆盖脸。

这是基于当前图像确定的形状，**不是已实现的自动小鸡眼睛关键点检测器**。换玩偶或姿态后要重新选眼部。

黑图背景与初始图做 `TM_CCOEFF_NORMED` 模板匹配，要求相关性 ≥0.85、平移 ≤2 px。成功轮相关性 0.973，位移 `(0,0)`。该检查只适用于本轮小幅平移判断，不保证发现任意旋转或深度变化。

### B. 用一个中心探针把初值移到脸上

沿用五圆前序标定的 `H`，中心探针半径为 5 投影像素。实拍检测到一个脸内亮点后：

```text
δ = 实测相机点 - H(实际取整的投影点)
H_face_initial = Translation(δ) × H
```

此时只补偿大幅位置偏差，不能认为曲率已经解决。后续仍须实测局部对应。

### C. 采集真正落在脸上的 12 个点

一次上传 4×3 探针，每点半径 4 投影像素。成功布局的预期相机坐标为：

```text
x = [421, 510, 623, 680]
y = [440, 480, 523]
```

用 `H_face_initial⁻¹` 映射、取整，生成一帧点阵。验收这组样本时要求：

1. 脸部 ROI 内恰好检测到 12 个紧凑亮点。
2. 每个预期位置的最近邻必须唯一，12 个索引不能重复。
3. 最大配对距离 ≤35 相机像素，否则不能强行配对。

**本轮关键失败：** 初版最右列取 `x=729`，脸内只检测到 9 点。检查本地 `chick_sunglasses_20261027_102521/face_grid_raw.png` 发现，另外 3 点落在后方标定板约 `x=857`，而非弱光漏检；公开保留[该轮失败报告](../captures/procalib/chick_sunglasses_20261027_102521/report.json)。右列收回到 680 后，12 点才全部落在可测脸部表面。

经验：相机看得见的曲面位置，不代表当前投影光线也能到达。不能把背景上的点混入脸部拟合，也不能仅降低检测阈值掩盖几何问题。

### D. 拟合局部二次映射，再做反向采样

对投影坐标 `(u,v)` 归一化：

```text
s = (u - 320) / 320
t = (v - 240) / 240
φ(u,v) = [1, s, t, s², s·t, t²]
[camera_x, camera_y] = φ(u,v) × C
```

用 12 组实测对应最小二乘求 `6×2` 系数矩阵 `C`。要求设计矩阵秩为 6，样本最大残差 ≤4 px；成功轮最大样本残差 **1.33 px**。

对每个投影仪像素求出它对应的相机坐标，再用 `cv2.remap(..., INTER_NEAREST)` 从目标相机掩模取值，得到 640×480 的二值位图。这样是在投影仪像素网格上反向采样，而不是把相机掩模直接缩放。

多项式只用于眼部局部。最终将有效投影范围限制在样本包围盒附近：`u` 下界扩 20 px、上界扩 15 px，`v` 两端各扩 10 px，其他像素置黑。不能把这个二次模型外推成整幅空间的通用标定。

### E. 模型拟合通过后，仍要看整幅墨镜的实际落点

[第一版整图报告](../captures/procalib/chick_sunglasses_20261027_102911/report.json)记录 IoU 为 0.854，但右镜片质心误差 **5.79 px**，超过事先设定的 5 px 上限，不能因为视觉上大致像就通过。对应原始相机帧仅留本地。

对实测轮廓与目标比较发现：右镜片质心约偏左 5.64 px、偏下 1.29 px。第二版使用局部反馈，期望右镜片向右 4.5 px、向上 1 px，左镜片不变：

```text
w = clip((mapped_camera_x - 565) / 60, 0, 1)
采样 camera_x -= 4.5 × w
采样 camera_y += 1.0 × w
```

这是反向采样坐标的修正，符号与光斑期望移动方向相反。配合上述局部范围调整，右镜片误差降至 0.60–0.86 px，未通过放宽验收阈值“制造成功”。

修正量来自本轮真实反馈，不是适用于所有玩偶的固定参数。保存的 `face_mapping.npz` 只有未加反馈的系数和探针对应；重建最终位图还需读取报告中的修正量并应用局部裁剪。直接复播应使用最终 `projector_mask.png`。

## 5. 验收指标如何计算

先重新投黑图、拍摄同曝光背景，再投墨镜。对每个投影帧：

1. 计算灰度增量，阈值为 **15**。
2. 限制在脸部 ROI；做 5×5 闭运算。
3. 保留面积 >50 px 的外轮廓并填充，形成实测轮廓掩模。
4. 在固定镜片区域内分别统计质心与覆盖率；每片须有至少 100 个实测掩模像素。

| 条件 | 阈值 |
|---|---|
| 整幅目标与实测轮廓 IoU | ≥0.75 |
| 左右镜片质心误差 | 分别 ≤5 px |
| 左右镜片目标覆盖率 | 分别 ≥80% |
| 超出目标膨胀范围的实测轮廓占比 | ≤10%；膨胀核为 15×15，即轴向 7 px 余量 |
| 标定板指定区域漏光指标 | ≤3% |
| 连续检查 | 3 次通过，再正常断连、重新拍摄 |

镜片统计区域分别是 `x=[420,556)`、`x=[592,719)`，共用 `y=[448,515)`。标定板漏光指标是 `x=[775,1180), y=[380,570)` 内超过增量阈值的像素数，除以目标墨镜掩模面积。

**指标边界：**

- 闭运算和轮廓填充会补上黑色瞳孔等造成的暗孔，覆盖率是处理后的形状覆盖率，不是每个眼部像素都收到了可测绿光。
- “质心误差 <1 px”不是整个边界的亚像素标定精度，也不是自动检测眼睛的误差。
- “漏光指标为零”只针对指定 ROI 和亮度阈值，不能表述为整个房间物理上绝无散射光。
- 三次验收是短时静态稳定性检查；播放参数 3600 秒不等于已经监测一小时。

## 6. 复用经验与停止条件

1. **先确认是真实的目标变化。** 从板换成玩偶后先拍新场景，不复用旧的目标坐标当最终答案。
2. **粗定位与精映射分开。** 板面 H 负责找到脸附近，中心探针处理大视差，局部点阵处理曲率，整图反馈处理剩余误差。
3. **判断未命中的原因。** 黑圆弱反射要改善曝光；本轮右列落到背景则是几何问题，两者不能用同一种补丁。
4. **少量多点采集优于大量逐点上传。** 本轮 12 个探针共用一次图像上传，减少 BLE 与 Flash 写入次数；设备连接始终保持在同一个桥进程内。
5. **保存目标、实测、映射和最终位图。** 只有漂亮预览图，无法判断是投准了还是软件画准了。
6. **成功后不要清黑图。** 保留循环播放，仅正常关闭 BLE；失败时若仍连接则请求黑图，若已掉线则不能保证软件关光成功。
7. **不可照搬到动态物体。** 当前没有运动跟踪、遮挡恢复或深度变化补偿；玩偶、相机、投影仪移动后要重新测量。
8. **可见但不可投的位置要诚实停止。** 若探针持续落到背景或被遮挡，需要调整摆位或设计，而不是让拟合吸收错误对应。

实测执行器原为会话脚本，现已整理为实验 CLI 并整合断连后自动复验。离线回归可从归档映射逐像素重建最终投影掩模，也会拒绝合成的错位和漏光用例；这不等于整理版重新做过硬件实验。本文不代表项目已经提供通用“一键给任意玩偶戴墨镜”的功能。

公开归档只包含报告、数值映射、目标/投影/实测轮廓二值掩模，原始照片留在本地并加入忽略规则。若再次复播保存位图，仍应先检查玩偶姿态，再实拍确认，不能只读取旧报告的 `passed`。
