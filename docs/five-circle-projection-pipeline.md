# 实机经验：绿光命中标定板的五个大圆

> 实验日期：2026-10-27。目标是五个真实光斑同时落在五个大圆内，不是仅发送成功，也不是把标注画在相机预览上。

## 1. 结果与证据

最终验收连续三次 **5/5 命中**，最大圆心误差 **3.59 相机像素**。断开 BLE 后再拍摄，仍然 5/5 命中，最大误差 **3.44 像素**。

## 2. 设备与运行前提

| 项目 | 本轮配置 |
|---|---|
| 投影仪 | Iris-G-B6B7CA，`F4:12:FA:B6:B7:CA`，640×480、1bpp |
| 相机 | 海康 MV-CA013-A0UM，序列号 `K65564865`，1280×1024 |
| 标定板 | CB-0300-W-001，11×9 点阵，5 个大圆 |
| 最终验收曝光 / 增益 | 40000 μs / 12 dB |
| 采集 | 每次打开相机后丢弃 4 帧，再平均 8 帧；采完关闭相机 |
| 上传后等待 | 2.5 秒，再采集 |
| 播放 | 组 1 单帧循环，设置 3600 秒；正常断开 BLE 不停止播放 |

相机、投影仪和板必须固定。地址只代表本次设备，换设备要重新扫描，不能把它写成通用默认值。相机接入见 [hik-camera.md](hik-camera.md)。

设备控制使用私有仓库 [rea-IrisGreen](https://github.com/shenyaoqiang45/rea-IrisGreen) 的 `agent/service.py`，不是在相机循环里反复创建 BLE 连接。需要该仓库的访问权限，接入契约在其 `agent/manifest.json`；默认将两仓库检出到同一父目录，也可用 `--bridge` 指定服务路径。

Windows 启动桥时显式使用 UTF-8，避免中文异常信息破坏 JSON 解码：

```powershell
python -X utf8 -u F:\2026\rea-IrisGreen\agent\service.py
```

通过同一个常驻进程的 stdin/stdout 顺序交换 JSON-RPC；stdout 只解析协议，stderr 记录日志。首帧使用本次补充的可选参数：

```json
{"jsonrpc":"2.0","id":1,"method":"device.connect","params":{"address":"F4:12:FA:B6:B7:CA"}}
{"jsonrpc":"2.0","id":2,"method":"display.show_frame","params":{"data_base64":"<38462 字节设备 BMP 的 base64>","clear_slot":true,"seconds":3600}}
```

`clear_slot=true` 仅清理组 1，然后上传；后续换图不再清组。它是本轮对兄弟仓库桥接实现增加的选项，旧版桥不一定支持，不能仅凭相同版本号认定可用。默认不清组的行为保持不变，相关单元测试覆盖清组顺序、参数错误与失败中止。

实验入口已整理为 [tools/aim_five.py](../tools/aim_five.py)。以下命令会控制真实设备；`--help` 不连接设备：

```powershell
python tools\aim_five.py --help
# 新摆位：重新测量引导点并修正
python tools\aim_five.py --address F4:12:FA:B6:B7:CA
# 只有固定摆位仍一致时才复用保存进度；仍会重新拍摄验收
python tools\aim_five.py --address F4:12:FA:B6:B7:CA --resume captures\procalib\five_circles_20261027_100519
```

支持 `--bridge`、`--serial`、`--out`；输出目录必须不存在，避免覆盖原始实验。未给地址时只允许自动选择唯一广播设备。脚本复用本仓库的位图打包函数，离线测试验证其字节顺序与本次桥接实验一致。

## 3. Pipeline

```text
扫描并选择设备 → 建立唯一 BLE 会话
→ 首帧清理组 1、投全黑 → 拍真实背景
→ 检测板范围和五个真实大圆
→ 五个引导点测 H → H⁻¹ 给出目标初值
→ 单点投射、拍摄、按误差修正
→ 五点合成一帧 → 三次同时验收
→ 正常关闭 BLE → 再拍摄确认仍在投射
```

### A. 先建立可信背景

不能用 `stop` 代替黑图：停止播放可能回到固件内置图案。必须上传全黑位图并播放，再拍摄确认。

第一轮虽然上传了黑图，实拍仍显示旧的 “Ri” 图案。原因排查指向组 1 残留帧参与轮播；首帧清理该组后，才取得无图案背景。这一步不能靠回包替代相机检查。

### B. 找真实的大圆，而不是盲信点阵编号

复用 [procalib.py](../irisloop/procalib.py) 的圆点检测和点阵匹配：

1. 自适应阈值检测暗圆；本轮依次尝试窗口 151、101、71、51，`cval=5`。
2. 要求至少匹配 90 个点，取得点阵凸包作为板内 ROI；成功轮匹配 99/99。
3. 在凸包内统计圆面积，中位数作为普通小圆面积参考。
4. 面积大于中位数 **2.5 倍**的候选必须恰好 5 个。
5. 按相机画面从上到下排序，直接使用实测质心；等效半径为 `sqrt(area / π)`。

本轮曾出现“某个规范 fiducial 编号对应小圆”的结果，半径约 11 px，而真正大圆约 22 px。不能因为返回了五个编号，就认为已找到五个大圆。这里改用真实面积确认目标，并未证明或修复所有点阵方向问题。

### C. 用少量引导点建立初始映射

逐个投射以下投影仪坐标，点半径 7 px：

```text
(320,240), (230,150), (410,150), (410,330), (230,330)
```

每次对背景做亮度差分，复用紧凑连通域检测，再限制在板的凸包内。必须恰好检测到一个点，且距凸包边界至少 25 相机像素；否则该样本不能用于拟合。

用五组 `projector → camera` 实测对应求单应矩阵 `H`。`H⁻¹` 只给初值，不作为最终准确度证明。

### D. 用实拍反馈修正单点

目标点记为 `t`，实测落点为 `c`，当前投影坐标为 `p`：

```text
e = t - c
J = [ H(p + (1,0)) - H(p), H(p + (0,1)) - H(p) ]
Δp = solve(J, e)
p_next = p + Δp
```

这里 `H(p)` 表示完成齐次归一化的映射。每次修正限制在 40 投影像素内，最多 8 轮；逐点修正阶段以圆心误差 ≤3 px 为目标。投影点半径 6 px，中心四舍五入到整数，且必须保留画面边界余量。

本轮第一点从约 5.38 px 修正到 0.79 px。前四点完成了逐点测量，第五点早期因为黑色印刷面反射太弱而漏检，不能把那一轮记作完整成功。

### E. 保存进度，避免掉线后全部重做

BLE 不稳定时，反复从头扫描、推引导点、重新修正会扩大失败窗口。本轮最终采用：

1. 复用 `five_circles_20261027_100519` 的 `H` 和前四点最新修正坐标。
2. 重新拍黑图，确认五个目标相对保存记录的最大位移 ≤1.5 px。
3. 第五点仍使用映射初值，不假称它已经通过逐点验收。
4. 只上传黑图和最终五点图，用最终三次实拍检验所有点。

这不是“沿用旧结果宣布成功”：**最终五个落点仍全部重新测量**。板位置检查本身不能发现投影仪单独移动，真正的落点验收不可省略。

## 4. 验收定义与实测数值

背景与投影帧必须使用相同曝光和增益。亮度差分阈值为 **8 灰度级**，连通域面积范围为 6–2000 px，并复用紧凑度过滤。

每次同时验收要求：

- 板内恰好 5 个可检测光斑，与五个目标一一对应。
- 每点圆心误差 ≤ `min(5 px, 0.25 × 大圆等效半径)`。
- 每个目标周围 `1.8 × 半径` 范围内，超过亮度阈值的像素至少 90% 位于圆内。
- 圆内超过阈值的像素至少 6 个。
- 连续三次通过，然后在正常断连后再次拍摄。

| 目标（从上到下） | 最终相机圆心 | 位图实际整数坐标 | 第三次误差 | 断连后误差 |
|---|---|---|---|---|
| 1 | (712.33, 329.85) | (361, 67) | 0.85 px | 0.78 px |
| 2 | (946.35, 452.61) | (201, 184) | 0.98 px | 1.22 px |
| 3 | (510.25, 497.80) | (490, 237) | 2.04 px | 1.78 px |
| 4 | (814.86, 611.60) | (285, 343) | 3.52 px | 3.44 px |
| 5 | (742.33, 618.88) | (333, 352) | 2.14 px | 1.97 px |

报告第五点保留浮点初值 `(332.6769, 351.9812)`，实际绘图取整为 `(333,352)`。三次平均帧中，按上述阈值定义的圆内光像素占比都是 100%；这不是“所有激光能量都在圆内”的物理测量。

## 5. 踩坑与可迁移经验

| 现象 | 实测处理与边界 |
|---|---|
| 扫不到设备 | 先检查手机是否抢连；换设备后重新扫描。设备屏幕显示连接成功不等于 GATT 和后续初始化完成。 |
| BLE 连接超时 / 上传中断 | 同一轮只保持一个连接，退出用 `service.shutdown` 或 stdin EOF；不要杀进程。无法恢复时才让用户重新上电。 |
| 相机与 BLE 同时工作不稳定 | 最后改为先连 BLE，上传期间不采流，采集完成后关闭相机。串行化便于排障，但之后仍发生过掉线，不能宣称已证明 USB3 干扰或彻底修复蓝牙。 |
| 黑图仍有旧内容 | 首帧显式清理组 1；后续只覆盖单帧，不反复删除。 |
| 把背景活动当光斑 | 首个引导点曾检出 7 个候选，其中多数来自板外人员活动；板 ROI 过滤后只剩真实激光点。 |
| 激光落在黑圆却检不出 | 早期阈值 20 过高；实拍回放验证阈值 8 可用。第五圆在 25 ms / 8 dB 下最大增量仅约 14，最终提高到 40 ms / 12 dB，而不是无限降低阈值。 |
| 误把通信用成功当完成 | 必须保存 raw、mask、数值报告，并做断连后检查。 |

## 6. 数据溯源与复用边界

- 最终报告的 `samples=[]` 是因为该轮是恢复验收；逐点历史在 `seed_from` 指向的前序目录。
- 最终目录的 `live_homography.npz` 保存了 `H`，但 `cam` 数组为空。要分析五组标定对应，应读取[前序完整标定数据](../captures/procalib/five_circles_20261027_100519/live_homography.npz)，不能把最终文件当成新采的五组样本。
- 最终报告 `board_movement_px=0` 来自恢复分支对同一背景的重复检测，不是全程零运动证明。
- 实测执行器原为会话脚本，现已整理为实验 CLI；不是通用自动标定产品。整理版保留光学算法与阈值，并补上断连后自动验收、恢复时保留原始点对、最终坐标边界检查。上述历史报告保持原样，不把整理后的代码行为倒填成历史实测结果。
- 坐标、阈值和曝光是这次固定摆位的实测配置；移动设备、换板深度或换设备都需重新验证。
- 3600 秒是设备播放参数，不是已连续监测一小时的证明；“断连后仍显示”只证明拍摄时刻的状态。若异常时已掉线，软件发黑图也不能保证设备实际熄光。
- 公开归档只包含数值报告、标定参数和二值掩模；原始相机帧及带人物背景的标注图留在本地，已加入忽略规则。不要为补齐图片链接而上传办公室旁人。
