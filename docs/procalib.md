# 相机-投影仪逆相机模型联合标定方案

海康工业相机 × IrisGreen 激光投影仪的完整内外参标定。核心思想：**把投影仪当作一台"逆相机"**——相机是 3D→2D 成像，投影仪是 2D→3D 逆成像，二者共用同一套针孔模型与标定算法，最终得到可用于三角化三维重建的双目系统。

## 1. 标定目标（输出物）

| 输出 | 含义 |
|---|---|
| K_c, dist_c | 相机内参 + 畸变（1280×1024） |
| **光线场** ray field | 投影仪逐像素光线表（origins+dirs，相机系）——**主模型** |
| K_p, dist_p, R, T | 针孔近似内外参（仅参考：IrisGreen 是双振镜 MEMS 激光，**不是针孔器件**，针孔拟合会发散） |
| report.json | 各级误差 + 光线场线拟合 RMS（>1mm 即警示装置被碰动过） |

全部存入 `captures/procalib/<run>/procalib.npz`。

> 实测教训（run1）：双振镜扫描 = 水平/垂直各有独立投影中心，针孔模型闭环失败
> （Zhang 闭式解 fy/fx=1.48、LM 陷入坏盆地）。改用无模型逐像素光线场：
> 同一投影像素跨姿态的 3D 点共线 → PCA 拟合直线得该像素光线。
> 另一教训：**装置（尤其投影仪）必须刚性夹紧**——run1 中同一投像素点在
> 相机画面中的位置跨姿态跳动达 ±20px，证明装置被碰动；采集已内置刚性自检
> （同一投影像素的相机坐标跳变 >5px 即作废当前姿态并报警）。

## 2. 硬件与已验证前提

- **相机**：海康 MV-CA013-A0UM（黑白 1280×1024，USB3，MVS SDK 5.1.0 已装）。接入与操作见 `docs/hik-camera.md`，封装 `irisloop/hik_camera.py`，冒烟 `tools/hik_smoke.py` 已验证。
- **投影仪**：IrisGreen 激光投影（640×480、1bpp、BLE 推图）。经验约束：
  - "关闭投影"= 推全黑图（`stop()` 会回落内置大象动画）；
  - 播放前需 `stop→play` 序列；推图后 settle ~0.8s；
  - 激光扫描条纹 → 用**短曝光 + 多帧平均**压制；
  - 推图慢（秒级/帧），采集设计须最小化推图次数。
- **标定板**：CB-0300-W-001 圆点板（白底黑点），规格见 `cbinfo/`：
  - 11 列 × 9 行 = 99 点，间距 25mm，覆盖 250×200mm；
  - 5 个大圆点为定向基准，规范网格坐标 `(2,4) (5,2) (5,6) (6,2) (8,4)`（任何旋转下不对称，唯一确定板方向，解决点阵朝向歧义）；
  - 布局文件 `cbinfo/CB-0300-W-001.layout.json`。

## 3. 方法流程

### 步骤 0：装置固定
相机与投影仪刚性固定（光学平台），共同对准标定板活动区域。**标定全程两者不可相对移动**（否则重来）。

### 步骤 1：相机内参（camint）
- 投影保持全黑；相机用**长曝光（~20-30ms）**。
- 手持标定板 15–20 个姿态（覆盖画面四角+中心、远近、俯仰偏航各 ~30°），每姿态自动检测圆点阵。
- 检测：黑点质心（阈值+圆度过滤，亚像素）→ 点阵拓扑匹配（基准点定方向）→ 得到 99 点 ↔ ini 的 mm 坐标对应。
- `cv2.calibrateCamera` → K_c, dist_c。期望 RMS < 0.5px。

### 步骤 2：投影引导（一次性）
- 逐点投影 5 个锚点（四角+中心，5 次推图），相机短曝光检测激光点。
- 得粗单应 H_boot（投影仪像素→相机像素）。装置固定期间 H_boot 持续有效。

### 步骤 3：投影点阵采集（collect，8–12 个板姿态）
每个板姿态两帧（仅 2 次 BLE 推图）：
1. **板帧**：投影全黑 → 长曝光拍板 → 检测圆点阵 → solvePnP(K_c) 得板平面在相机系的位姿。
2. **点帧**：投影整幅激光点阵图（~10×8 点，一次推完）→ 短曝光 + 多帧平均 → 背景差分检测所有激光点质心。
3. **匹配**：H_boot 把每个检测点预测到点阵索引（最近邻 + 容差 ~15px）；匹配率 <60% 自动重跑锚点引导。
4. **求 3D**：每个投影仪像素 ↔（相机光线 × 板平面交点）→ 3D 点（相机系）。

要点：投影点尽量落在板面圆点**之间**的空白处（点阵位置错开 25mm 网格，如按半间距偏移），避免激光打进黑点损失对比度。

### 步骤 4：解算（solve，离线）
- **光线场（主）**：按投影像素分组，逐像素稳健直线拟合 → 光线表（origin+dir，相机系）+ 共点性参考中心；线拟合 RMS 是数据质量的核心指标（应 <0.5mm）。
- 针孔近似（参考）：`cv2.calibrateCamera`（物体点=各姿态 3D 点，图像点=投影仪像素）→ K_p；`cv2.stereoCalibrate`(FIX_INTRINSIC) → R, T。带自适应坏姿态剔除（阈值 min(2.5px, max(0.8, median×1.8))）。

### 步骤 5：验证（verify）
- 2–3 个**新**板姿态（不参与解算），相机光线 × 投影光线场插值三角化 → 拟合平面，报点到面 RMSE(mm)。
- 达标参考：光线场线拟合 RMS <0.5mm、verify 平面 RMSE ~1mm 内；不达标按 report.json 定位。

## 4. 软件结构

- `irisloop/procalib.py`（新建，主模块，`python -m irisloop.procalib <子命令>`）：
  - `camint` / `collect` / `solve` / `verify` 四个子命令；
  - 纯函数求解核心（无硬件依赖，可测）：`detect_board_dots`、`match_lattice`（基准点定向）、`detect_grid_dots`、`assign_grid_indices`、`rays_to_board`、`solve_camera_intrinsics`、`solve_projector`、`solve_stereo`。
- 复用：`hik_camera.HikCamera`、`ble_client.IrisBleClient`、`loop.push_image`、`image_pack.build_stream`、`protocol.cmd_delete_group`、calibrate.py 的 BLE 播放序列参数。
- 测试：`tests/test_procalib.py`（合成数据：已知 K_c/K_p/R/T 正演生成对应点，验证反解精度；匹配算法乱序/缺点/离群用例）。
- 数据集落盘：`captures/procalib/<timestamp>/`（intrinsics/ 板帧、poses/poseNN/{board.png,grid.png,dots.json}、procalib.npz、report.json）。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 激光扫描条纹 | 短曝光 1–3ms + 多帧平均（grab_average） |
| 激光点落进板面黑点 | 投影点阵位置错开 25mm 网格半间距 |
| 板姿态间视差使 H_boot 失配 | 网格间距远大于匹配容差；匹配率 <60% 自动重锚 |
| BLE 推图慢 | 每姿态仅 2 次推图，全程 ~30 次 |
| 圆点阵方向歧义 | 5 个大基准点唯一定向（已验证解析） |
| 装置移动 | 步骤 0 刚性固定；verify 误差突增即警示重标 |

## 6. 手绘区域的平面跟踪

运行 `python tools/aim3d.py`，在物体暂时静止时按住鼠标画闭合区域，
松开后使用区域内部的自然纹理跟踪物体，不需要 AprilTag / ArUco。
绿色轮廓表示相机中的跟踪结果，**不代表当前实际激光落点**。
`r` 清除选区并请求黑图；重新绘制可重新锁定；`q` / Esc 退出。
`--static` 保留原来的固定选区模式，`--at X Y` 保留单点校正模式。

适用范围：相机与投影仪固定、刚性物体在参考深度附近平移和面内旋转。
选区应完全位于同一物体的有纹理表面，避免包含背景；绘制期间保持物体静止。
算法使用前后向光流检查和 RANSAC，从初始特征到当前特征估计相似变换。
纯色、反光、遮挡、运动模糊或激光覆盖造成的纹理消失可能导致失锁。
失锁、画面读取失败或区域完全离开投影范围后请求黑图，必须重新画选区，
不会自动切换到其他目标。部分超出投影画面的区域会被裁剪。

这仍是**平面近似验证工具，不是任意三维表面跟随**：投影映射仍使用固定
参考深度的单应矩阵，不能补偿前后移动、倾斜或变形。尺度变化过大时会拒绝
继续跟踪，但该检查不能可靠检测所有深度和倾斜变化。

相机处理与 BLE 上传异步运行，上传忙时仅保留最新待发图，不积压历史位置。
实际投影仍受整图上传、停止/播放和设备刷新限制，不能保证实时贴合。
控制台 `projection upload=...s` 是主机端上传/播放调用耗时，不是实际出光延迟。
